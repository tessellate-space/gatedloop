# Design

## Context

See proposal.md for the motivation. The relevant current state in `bin/gates`:

- `_tests_defect` validates `--kind` and a non-empty `--detail`, applies the per-kind caps (`MAX_TEST_DEFECTS_BY_KIND`) and appends a `test-defect` row. Past the `assertion` cap, its refusal quotes the earlier defects' details only.
- A handoff row (`TESTS_HANDOFF_EVENT`) records each task's held tests as `{path: blob}`; `_authoring_state` folds them, a `--task` handoff replacing that task's entry. So "did the held tests change since the previous handoff" is a blob comparison the shim can already make.
- `gates tests check` already locates a task's latest placement and the first run of its oracle gate after it (the red-after-placement check). The `green` evidence check reuses that lookup, asking for a passing run instead.
- The author's defence exists only in its report to the dispatcher (`agents/test-author.md`, re-dispatch paragraph).

## Goals / Non-Goals

**Goals:**

- Neither side of a dispute can make a claim the shim cannot resolve.
- The ledger holds the whole exchange, so a human reading a halt sees both positions.

**Non-Goals:**

- Judging whether a citation supports the claim. The shim checks that the cited evidence exists, not that it proves the point. That judgement stays with the other agent and, past the cap, the human.
- Changing the caps or the halt causes.
- Citations on authored-set review findings (the convention review's findings already cite a rule-id).

## Decisions

**D1. Three citation forms, resolved against the change branch's worktree.** `path` and `path:line` (`path:a-b` for a range) resolve when the file exists in the worktree and the line or range is within it. A path is resolved against the worktree root only: a placed test is cited at its real path, and a held copy, which exists only until its task is placed, by its own path under the holding area `.gatedloop/authored/<change>/<N.M>/…​.authored` (in practice the author's defence). Placement removes a task's holding files, and `tests handoff --task` refuses a task whose holding directory holds nothing, so the author defends a placed task by first rewriting each of its held copies at `<N.M>/<path>.authored`, byte-identical to the placed file (the locked content), then handing off with `--defend`: the held blobs then equal the previous handoff entry, and the held copy is citable. `spec:<capability>#<scenario>` resolves when a `#### Scenario: <scenario>` exists under that capability in the change's delta specs or in `openspec/specs/`, matched case-insensitively with whitespace collapsed. Alternatives considered: free-form URLs (unresolvable offline, rejected) and symbol names (would need a language-aware index, against `zero-dep-shim` and `stack-agnostic-prompts`, rejected; `path:line` covers a symbol).

**D2. `--cite` is repeatable and required for `setup` and `assertion`, not for `green`.** A `green` defect's claim is a fact about a run, and the run is in the ledger, so the shim checks the run instead of asking the agent to point at it. That is stronger evidence than any citation.

**D3. The defence is a flag on `tests handoff`, not a new subcommand.** A defence already is a handoff of unchanged tests (`agents/test-author.md`), so `--defend` makes that existing act carry its reason. The shim refuses `--defend` when the task's held blobs differ from its entry in the previous handoff state, or when no `test-defect` row for the task follows its previous handoff. The `test-defence` row is written next to the handoff row, in the same call.

**D4. Show and the cap refusal read the exchange from the ledger in order.** Defects and defences for a task are interleaved by ledger order, so a reader sees "defect, defence, defect" as it happened.

**D5. Default-on, keyed on the handoff row.** New handoff rows carry `"disputes": "cited"`. The checks in D1–D3 apply when the task's governing handoff row has it, so a task handed off before the upgrade keeps the old rules until it is next handed off, by a full handoff or a `--task` handoff of that task. Alternative considered: a manifest key. Rejected because the checks only constrain the plugin's own agents, adopters configure nothing, and a key would offer a way to switch off a guarantee the loop already claims. This needs the maintainer's approval, because the standing rule is that new adopter-facing behaviour is opt-in unless the plan says otherwise. The plan PR asks for it.

**D6. The names the tests pin.** Every task's tests are written before any of it is implemented, so these are fixed here:

- The resolver is `unresolved_citations(root: Path, change: str, citations: list[str]) -> list[str]`, module-level in `bin/gates`. It returns the citations that do not resolve, in input order, and an empty list when all do. `root` is the worktree root, and `change` is used only to locate the change's delta specs. The resolver never searches the holding area: a held copy resolves only by its full path `.gatedloop/authored/<change>/<N.M>/<path>.authored`, which is under the root like any other path. A path citation resolves only to a regular file inside the root, with 1-based lines: an absolute path, a path escaping the root through `..`, a directory, line `0`, a non-numeric `:` suffix, a range whose start is greater than its end (`path:14-10`), and a range starting or ending after the file's last line each do not resolve.
- Two ledger fields are appended to `LEDGER_ROW_FIELDS` after `v`, in this order, per the union rule: `disputes` (`"cited"` on a `tests-handoff` row written by this shim; `None` on every other row) and `cites` (the list of citations, as given, on `test-defect` and `test-defence` rows; `None` on every other row, and on a `green` defect). The row version stays 1. A defect's `cites` is the list given; a `green` defect takes no `--cite` (refused, D2: its evidence is the run), so its `cites` is `None`, as is a citation-free defect's under an older handoff.
- The governing handoff of a task is the latest `tests-handoff` row that is a full handoff (`task` is `None`) or a `--task` handoff of that task. The citation requirement and the passing-run check apply when that row has `disputes: "cited"`. The defence checks are not keyed: `--defend` and `--cite` on `tests handoff` are new flags, so no in-flight agent passes them, and they are checked under any handoff. Citations given under an older handoff are still resolved (a bad one is refused) and stored.
- A `green` defect's passing run must be recorded after the latest `tests-placed` row carrying the task, read from the ledger, so a run before a re-placement does not count.
- The defence row has `gate: "test-defence"` (a constant beside `TEST_DEFECT_EVENT`, and in `NON_GATE_EVENTS`), the task in `task`, the `--defend` reason in `detail` and its citations in `cites`. It is appended directly after the handoff row of the same call.
- `--defend` requires `--task`, at least one `--cite`, and no `--dry-run` (a dry run records nothing, so it cannot record a defence); `--cite` without `--defend` on `tests handoff` is refused. Each refusal exits 1 and writes nothing.
- `gates tests show --json` keeps every existing key and each `defect_log` entry's shape. It adds one top-level key, `exchanges`: `{task: [entry, ...]}` in ledger order, each entry `{"event": "test-defect" | "test-defence", "kind": <defect kind, a legacy kindless row reading as `assertion` as in `defect_log`, or None for a defence>, "detail": ..., "cites": [...]}` (`[]` when the row has none). `exchanges` lists only tasks that have at least one defect or defence. The text form prints, under each task, each defect line as now and each defence as `        defence: <detail>`, in ledger order, each followed by `          cites: <c1>, <c2>` when the row has citations and by no line when it has none.
- The refusal past the `assertion` cap keeps its current wording (the halt command, `oracle-conflict`) and replaces the `; `-joined details with one line per `test-defect` and `test-defence` row for the task, in ledger order: `  defect <n> (<kind>): <detail>` (a legacy kindless row's kind reads as `assertion`) or `  defence: <detail>`, each followed by `    cites: <c1>, <c2>` when the row has citations. Each `detail` appears verbatim. `<n>` counts the task's defects from 1 in ledger order; defences are not counted.
- The passing-run check of D2 is keyed on the governing handoff like the citation checks (D5): under a handoff without `disputes`, a `green` defect is recorded as before. The `--cite` refusal for `green` is not keyed: `--cite` is new, so no in-flight agent passes it, and it is refused under any handoff. 1.2 adds that refusal with `--cite`; 2.1 adds only the passing-run check.
- `gates tests defect` checks in this order and reports only the first that fails, exiting 1 and writing nothing: (1) `--kind`, (2) `--detail`, (3) a handoff is recorded, (4) `--cite` with `--kind green`, (5) the kind's cap, (6) under a cited governing handoff, a `setup` or `assertion` defect has at least one `--cite`, (7) every citation resolves, under any handoff (naming each that does not), (8) under a cited governing handoff, a `green` defect has a passing run of the task's oracle gate after its latest placement (a task never placed has none). (1), (2), (3) and (5) are today's checks, unchanged.
- `gates tests handoff` with `--defend` or `--cite` checks in this order, each refusal exiting 1 and writing nothing: (1) the flag refusals (`--cite` without `--defend`, `--defend` without `--task`, with `--dry-run`, or without a `--cite`), before the holding area is read; (2) today's handoff refusals, unchanged; (3) the task's held blobs equal its entry in the previous handoff state; (4) a `test-defect` row for the task follows its previous governing handoff; (5) every citation resolves, naming each that does not.

**D7. Each task regenerates the contract it changes.** `tests/test_contract.py` fails `ci` on any difference between the code and `tests/contract.json`, and `ci` runs before every commit. `tests/test_parser_characterization.py` likewise fails on any flag difference from `tests/parser-structure.json`. So the task that changes the public surface rewrites both snapshots (`python3 tests/test_contract.py --write`, `python3 tests/test_parser_characterization.py --write`) in its own commit: 1.2 (`--cite` on `tests defect`, the `disputes` and `cites` fields) and 3.1 (`--defend` and `--cite` on `tests handoff`). 1.1, 2.1 and 3.2 add no flag, field or document key either snapshot records. Each new-behaviour task's tests go in a file of its own (1.1 `tests/test_dispute_citations.py`, 1.2 `tests/test_cited_defects.py`, 2.1 `tests/test_green_evidence.py`, 3.1 `tests/test_defence.py`, 3.2 `tests/test_exchange_show.py`), so no two tasks hold the same new file. The same holds for existing tests that pin what a task changes: the task declares each under `rewrites:` on its oracle tag, so its author can read and rewrite it. Stamping `disputes` on every new handoff makes every existing test that records a `setup` or `assertion` defect after a real handoff need a `--cite`, and the passing-run check makes every existing test that records a `green` defect need a passing run first. Each such file is rewritten by the first task whose code breaks it, and that rewrite already holds under the later tasks' rules, so no file is rewritten twice.

## Risks / Trade-offs

- [Agents cite something trivially resolvable, such as the test file itself, to get past the check] → Accepted. The check only removes the evidence-free claim. Whether a citation is to the point is still judged by the other side, and the cap still brings in a human. The prompts say what a useful citation is.
- [A spec scenario renamed mid-change breaks a recorded citation] → Citations are resolved once, when recorded. A later rename does not invalidate a row.
- [More refusals mean more halts in unattended runs] → A refusal is immediate and names the fix (add `--cite`). It costs a retry, not a halt.

## Migration Plan

None beyond D5: in-flight changes keep the old rules. Rollback is reverting the change; the new row kind and fields are extra data in the ledger.
